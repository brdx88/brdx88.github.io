# AGENTS.md

This repository hosts Brian Cusuanto's personal website and will evolve from a single-page portfolio into a broader personal platform.

## Project intent

- Position Brian as a data engineer and builder.
- Support multiple goals in one website:
  - personal brand / about page
  - portfolio and case studies
  - consultancy landing page
  - optional links to other products or portfolios
- Keep the site deployable on GitHub Pages unless explicitly changed.

## Preferred working style

- Start from the existing content before inventing new messaging.
- Preserve factual accuracy for work history, projects, and claims.
- Prefer simple, maintainable solutions over heavy tooling unless there is a clear benefit.
- Keep the experience fast, responsive, and easy to update.
- Favor reusable sections/components and clean information architecture.

## Tech preferences

- Current stack is static HTML, CSS, and JavaScript.
- Prefer staying framework-light unless a migration is clearly worth it.
- If proposing a new dependency or framework, explain the tradeoff first.
- Keep GitHub Pages compatibility in mind.

## Content rules

- Do not remove existing projects or experience entries without a clear reason.
- New copy should sound credible, clear, modern, and not overhyped.
- Prefer concrete business outcomes over generic claims.
- If business/consultancy messaging is added, keep it consistent with Brian's actual strengths in data engineering, automation, analytics engineering, and data platform work.

## Design direction

- Avoid generic template-like portfolio design.
- Keep the site feeling professional, modern, and intentional.
- Balance technical credibility with approachability.
- Design should work well on desktop and mobile.

## Analytics guidance

- The user wants to track how many people visit the site.
- Prefer privacy-conscious analytics or lightweight visitor counting solutions.
- Any analytics implementation should be easy to maintain on a static-hosted site.

## Documentation expectations

- Keep `PROJECT_BRIEF.md`, `CONTENT.md`, and `TODO.md` updated as the project evolves.
- When major structure decisions change, reflect them in the docs before or alongside implementation.

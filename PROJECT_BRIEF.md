# Project Brief

## Summary

This website started as a personal portfolio for Brian Cusuanto. It is now intended to grow into a personal website that can support multiple entry points:

- personal brand and introduction
- technical portfolio and project showcase
- consultancy landing page
- optional links to other portfolios, products, or business initiatives

The current site is a single-page static portfolio and should evolve without losing clarity or credibility.

## Primary goals

- Present Brian as a strong, credible data engineer with real delivery experience.
- Make it easy for visitors to understand:
  - who Brian is
  - what he does
  - what he has built
  - how to contact or work with him
- Create room for consultancy/business messaging without making the site confusing.
- Track website visits in a lightweight way.

## Current state

- Single-page website
- Static stack: HTML, CSS, JavaScript
- Sections:
  - About
  - Experiences
  - Projects
- Hosted as GitHub Pages custom domain setup via `CNAME`

## Desired future state

- More flexible navigation beyond a single scrolling portfolio
- Clear distinction between:
  - personal profile
  - portfolio/case studies
  - consultancy/services
- Easier content expansion over time
- Visitor analytics or counter

## Target audiences

- Recruiters / hiring managers
- Potential consultancy clients
- Collaborators and founders
- Peers in data / analytics / engineering

## Core value proposition

Brian helps organizations turn messy, fragmented, or manual data work into reliable, scalable, analytics-ready systems.

## Key strengths inferred from current website

- Data engineering
- ETL / ELT pipelines
- Big data processing
- Analytics engineering mindset
- Workflow automation
- Banking and enterprise data experience
- Hands-on Python, PySpark, SQL, Airflow, dbt, Docker, and cloud tooling

## Business/consultancy direction

Needs clarification from Brian, but likely includes:

- data pipeline design
- workflow automation

- modernization of manual reporting or delivery processes
- fractional data engineering / advisory support

## Visitor tracking requirement

The website should show or at least collect visit counts.

Possible implementation paths to evaluate later:

- Google Analytics
- Plausible
- GoatCounter
- custom pageview counter compatible with static hosting

## Constraints

- Prefer GitHub Pages-friendly solutions
- Prefer low-maintenance architecture
- Keep performance strong
- Avoid unnecessary complexity too early
